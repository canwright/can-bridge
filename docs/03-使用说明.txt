================================================================
  ⚠ 重要：有一类 ZCANPRO 版本暂时不支持（2026-11-04 实测）
================================================================

  判断方法（10 秒就能看出来）：
    看 E:\ZCANPRO\ 目录里【有没有 USBCAN.dll】

      ┌ 有 USBCAN.dll（几十 KB）→ 这种版本可以装桥 ✅
      └ 没有 USBCAN.dll          → 这种版本暂时别装 ❌

  为什么：
    新版 ZCANPRO（比如 2.4.1）不用 USBCAN.dll 这个 VCI 插件了，
    它走 zlgcan.dll + kerneldlls 那一套。
    往这种版本里装桥，会出现：

      · 桥凭空新建一个 USBCAN.dll（原本不存在，所以没有原厂可备份）
      · 桥走 VCI 路径，找不到能驱动这个盒子的 USBCAN_E.dll
      · 结果：ZCANPRO 打开设备失败，甚至「未响应」
      · 卸载后也没法还原（因为原本就没有这个文件）
      · 只能重装 ZCANPRO 才能恢复

  已经装错了怎么办：
    1. 点「一键卸载」
    2. 如果还是打不开设备 → 重装 ZCANPRO（不用重启电脑）
    3. 或者把 E:\ZCANPRO\kerneldlls\USBCAN.dll 复制到 E:\ZCANPRO\

  以后要支持这类版本：
    桥需要改成走 zlgcan.dll（ZCAN_* 接口）的内部后端 ——
    那也是 ZCANPRO 原厂走的那条路，做完就通用了。
    目前【未做】，暂缓。

==============================================================
  这是什么
==============================================================

  让【别的牌子】的 CAN 盒子，能在【周立功 ZCANPRO】里直接使用。

  也就是说：

      创芯 CANalyst、PEAK PCAN，插上以后
      在 ZCANPRO 里选「USBCAN-I」或「USBCAN-II」，
      点「打开设备」就能用 —— 不用再买周立功的盒子。

      （周立功自己的盒子当然也能用，桥装不装都不影响它。
        装的时候会先备份原厂 DLL，卸载就还原。）

  原理：
      桥被装成 ZCANPRO 目录里的 USBCAN.dll。
      ZCANPRO 以为自己在跟周立功设备说话，
      桥把每个调用转发给你真正插着的那个盒子。

  安全性：
      · 原厂 USBCAN.dll 原封不动备份成 USBCAN.dll.zlg.bak
      · 一键卸载就还原，完全不影响厂家自己的软件
      · 桥自己能判错，判不过就回退原厂 DLL 透传

==============================================================
  CAN 多盒子共存 万能桥 v3
  —— 一个 exe，三个按钮，谁都能用
==============================================================

  ★ 直接双击「一键工具.exe」，然后：

       [ 一键安装 ]   →  打开 ZCANPRO，型号选「USBCAN-I」或「USBCAN-II」
       [ 一键诊断 ]   →  出问题时点这个，它告诉缺什么
       [ 一键卸载 ]   →  恢复原样，和装之前完全一样

  ★ 只装一个文件：kerneldlls\USBCAN.dll

       因为它同时对应两个型号（dll_cfg.ini 里两行都指向它）：
           USBCAN-I    型号 3，1 个通道
           USBCAN-II   型号 4，2 个通道

       其它型号的 DLL（USBCAN_E.dll、USBCAN_4E_U.dll 等）一个字节都不动，
       所以插原厂盒子时走的还是厂家自己的驱动。

  ★ 通道数怎么算：

       型号决定"最多几路"，实际几路由硬件决定 ——
       盒子有几路就能用几路，多出来的槽干净失败，不会乱。

       例：PCAN-USB（1 路）选 USBCAN-II，只有通道 0 能用。

  就这么三步。不用看配置、不用改文件、不用命令行。


【它做什么】

  让 PCAN / 广成 / TOSUN / Kvaser / Vector 这些牌子的 CAN 盒子，
  也能在周立功的 ZCANPRO 里用。


【为什么不影响厂家自己的软件】

  两个层面都保住了：

  1. 安装前，原厂 USBCAN.dll 会备份成 USBCAN.dll.zlg.bak，
     卸载时原样还原（字节级一致，校验过才删备份）。

  2. 桥里有「原厂透传」：如果它认不出你插的盒子（比如插的是
     真周立功 USBCAN-II），会自动退回原厂 DLL 去处理 ——
     行为跟没装这个桥一模一样。

  第二条是关键。没有它，装了桥之后真周立功盒子反而打不开了。


【一键诊断会告诉你什么】

  · ZCANPRO 装在哪个目录
  · kerneldlls 里缺哪些驱动 DLL（残缺安装一眼看出来）
  · 有没有发现第三方驱动（PCAN/广成/TOSUN/Kvaser）
  · 内核驱动装了没（ZLGCAN / PEAK）
  · 结论 + 下一步该干什么

  诊断结果同时写到桌面：万能桥-操作日志.txt


【注意】

  · 会弹 UAC，点「是」（要往 Program Files 里写文件）
  · 装之前先关掉 ZCANPRO
  · 本工具需要和 _prog\UniVciBridge.dll 放在同一个文件夹里

 先说一个更大的问题：你的 ZCANPRO 可能是「残缺安装」
--------------------------------------------------------------

  检测驱动.bat 会解析 kerneldlls\dll_cfg.ini，把它声明的每个驱动 DLL
  和实际文件逐一对照。

  本机实测结果：
      dll_cfg.ini 声明了 80 条映射，涉及 35 个驱动 DLL
      实际只有 14 个 → **缺 21 个**

  缺的那些直接导致这些型号打不开：
      USBCAN_E.dll       型号 20,21     ← USBCAN-E-U / 2E-U
      USBCAN_4E_U.dll    型号 31
      USBCAN_8E_U.dll    型号 34
      PCI51XXE.dll       型号 1,7
      PCI9810/9820/9820I/9840B.dll
      pcie9110/9120/9140/9221.dll
      pci5010p/pci50xx_u/topcliff_can.dll
      CANDTU.DLL         型号 32,37
      CANDTU_MINI.dll    型号 33
      CANFDBlue.dll      型号 54
      CAN_REPLAY.dll     型号 35
      xpcfd.dll / zpcfd.dll

  ★ 这是「只复制了部分文件」的典型症状。
    根本修法是**用完整的 ZCANPRO 安装包重装**，
    而不是一个个补 DLL（补了也未必版本匹配）。

  只有 USBCAN-I/II（型号 3/4）、CANFD 系列、CANDTU-NET 这些是真的能用的。
--------------------------------------------------------------
 关于 USBCAN-2E-U（必须说清楚）
--------------------------------------------------------------

  实测确认（解包了 ZLG 的 USBCAN_AllInOne 安装包）：

    · 包内只有 usbcan.dll + usbcan.sys，**没有 USBCAN_E.dll**
    · 它的 INF 只匹配一个硬件 ID：
          USB\VID_0471&PID_1200      →  "ZLG USBCAN"
      也就是 USBCAN-I / USBCAN-II 那一代
    · 而 dll_cfg.ini 里型号 20/21（E-U / 2E-U）指向 USBCAN_E.dll

    结论：
    → 装 USBCAN_AllInOne **不会**让 2E-U 能用
    → 2E-U 需要 ZLG 针对 E-U 系列的单独驱动包（含 USBCAN_E.dll）
       装上后 USBCAN_E.dll 会出现在 kerneldlls
    → 在那之前，ZCANPRO 里选「USBCAN-2E-U」必然打不开

  哪里拿 USBCAN_E.dll（实测过的信息）：
    · 周立功资料页（2026-11 访问正常）：
        http://www.zlgcan.com/zlgcan-usbcan-ii/981/
    · 该页列出的两个直链目前返回 404（ZLG 站点过期）：
        CAN-bus-ZCANPRO_Setup.rar
        USBCAN_I_II_2A_drive.rar
    · 所以最可靠的办法是：
        a) 用你手上能正常安装的 ZCANPRO 完整安装包重装一遍
           —— 装完 kerneldlls 里就会有 USBCAN_E.dll
        b) 或者找 ZLG 售后要「USBCAN-E-U / 2E-U 驱动」

  检测驱动.bat 会明确把这一项列出来，装好后自动变 [OK]。

--------------------------------------------------------------
 桥的技术细节
--------------------------------------------------------------

  对外导出 14 个函数，和 ControlCAN.dll 完全一致：
      VCI_OpenDevice    VCI_CloseDevice   VCI_InitCAN     VCI_StartCAN
      VCI_ResetCAN      VCI_ClearBuffer   VCI_GetReceiveNum
      VCI_Transmit      VCI_Receive       VCI_ReadBoardInfo
      VCI_ReadErrInfo   VCI_ReadCANStatus VCI_GetReference
      VCI_SetReference

  后端（同目录 UniVciBridge.ini 里 backend= 指定）：
      pcan / gcan / tosun / kvaser / vector / vci

  几个关键实现（都是踩过坑的）：
    · 通道数钳位：广成驱动会把通道数报成 50（实际 2），
      ZCANPRO 按这个数遍历会越界闪退。桥强制钳到 1~4。
    · VCI_SetReference(RefType=0) 真设波特率；若在 OpenDevice 之前
      被调用（底层会拒绝），先缓存、Open 后补发。
      USBCAN-2E-U 必须走这个时序。
    · 波特率常量用官方对照表，不靠公式反推（推错总线全静默）。
    · Vector 的 xlCanSetChannelBitrate 必须在激活通道之前调用，
      桥里按这个顺序做了。
    · DllMain 只做最轻的事，不加载后端、不读配置（loader lock 安全）。
    · 纯 KERNEL32 依赖，不需要任何 VC++ 运行库。
