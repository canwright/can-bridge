================================================================
  启用 GitHub Actions 自动编译
================================================================

  ci-build.yml.txt 就是完整的 workflow 内容（纯 YAML，可直接复制）。
  本文说明为什么要绕这一下，以及怎么启用。


────────────────────────────────────────────────
  为什么它叫 ci-build.yml.txt 而不是 build.yml
────────────────────────────────────────────────

  改动 .github/workflows/ 里的文件，令牌必须带 workflow 权限。
  只有 repo 权限的令牌会被 GitHub 直接拒绝：

      refusing to allow a Personal Access Token to create or update
      workflow `.github/workflows/build.yml` without `workflow` scope

  所以先放在 docs/ 里：用 repo 权限就能提交，内容也随仓库保存。
  想启用时再复制到 .github/workflows/build.yml。


────────────────────────────────────────────────
  启用方式（两种，选一种）
────────────────────────────────────────────────

  【方式一】网页上建 —— 不需要任何令牌，30 秒

    1. 仓库页 → Add file → Create new file
    2. 文件名填：
           .github/workflows/build.yml
       （输入斜杠会自动建目录）
    3. 把 ci-build.yml.txt 的全部内容粘贴进去
    4. 拉到底 → Commit changes

    提交后立刻生效，Actions 页就能看到。


  【方式二】用带 workflow 权限的令牌

    生成令牌时多勾一项：  Scopes:  ☑ repo   ☑ workflow

    然后本地执行：

        git mv docs/ci-build.yml.txt .github/workflows/build.yml
        git commit -m "Enable CI"
        git push


────────────────────────────────────────────────
  这个 CI 做什么
────────────────────────────────────────────────

  · 在 windows-latest 上把全部源码按【32 位】编译一遍
        （上位机都是 32 位，64 位 DLL 它们加载不了）

  · 跑两个不需要硬件的测试
        CtConvTest      帧转换往返 50 项
        VxlLayoutTest   XL 结构布局 8 项（无 Vector 驱动时只做静态部分）

  · 上传编译产物，方便下载验证

  · 三道仓库卫生检查，任何一道不过就让构建失败：
        ① 不许提交厂商二进制（ControlCAN / USBCAN_E / PCANBasic / vxlapi ...）
        ② 不许提交厂商 PDF（有版权，只放官网链接）
        ③ 不许提交编译产物（*.obj / *.exp / out/）


────────────────────────────────────────────────
  为什么这些检查值得放进 CI
────────────────────────────────────────────────

  这个项目很容易不小心把厂商 DLL 提交进来 ——
  它们就在开发机的程序目录里，随手一复制就进仓库了。

  而厂商 DLL 各有 EULA，不允许再分发。
  一次误提交就会让整个仓库变成侵权状态，而且历史里删不干净。

  所以在 CI 里硬拦，比靠人记得可靠。

  同一条规则也适用于凭据文件：
  曾经有个 git 凭据临时文件被误提交过（里面是明文令牌），
  所以 .gitignore 里现在专门挡了这类文件名。
