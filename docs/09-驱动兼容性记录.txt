================================================================
  驱动兼容性记录
  2026-11-05 实测
================================================================

  背景：一台 Windows 11 25H2（Build 26200）的机器上，
        插上 ZLG 老款 USBCAN-II 后设备管理器显示【黄色感叹号】，
        ZCANPRO 打不开设备，桥也探测不到：

            VCI: USBCAN_E.dll 导出齐全，但打不开任何设备
            vci: 没找到能打开设备的 VCI 兼容库

  ★ 注意这个症状很容易误导：DLL 都在、导出齐全，
    看起来像"桥的问题"，其实是设备根本没起来。


────────────────────────────────────────────────
  一、症状与错误码
────────────────────────────────────────────────

  设备管理器：
      名称  : ZLG USBCAN
      状态  : Error（黄色感叹号）
      ID    : USB\VID_0471&PID_1200\ECAN21302231
      服务  : ZLGCAN
      Code  : 39  (ProblemStatus = 0xC000007B)

  手动启动服务：
      sc start ZLGCAN
      → 由于发生错误 193，StartService 失败。

  系统日志：
      Event ID 219  驱动程序\Driver\ZLGCAN加载失败

  0xC000007B = STATUS_INVALID_IMAGE_FORMAT
  错误 193     = ERROR_BAD_EXE_FORMAT

  ★ 这两个都指向"映像本身不可用"，不是"找不到文件"、
    也不是"签名无效"。


────────────────────────────────────────────────
  二、真正的原因：PE 头的子系统版本是 1.10
────────────────────────────────────────────────

  读 PE 可选头（PE32+ 布局）：

      字段                     usbcan.sys(2017)   USBCAN_E_U.sys(2020)
      ----------------------   ----------------   -------------------
      架构                     x64                x64
      Subsystem                1 (NATIVE)         1 (NATIVE)
      MajorSubsystemVersion    1.10  ★            6.1   ✓
      MajorOperatingSystem     6.1                6.1
      MajorLinkerVersion       9.0                9.0

  Windows 10/11 的内核加载器要求驱动子系统版本 ≥ 6.0，
  1.10 是 XP 时代的值，于是直接拒绝加载，返回 0xC000007B。

  ★ 判断方法（不用装任何工具）：
      读 PE 头 → 定位 e_lfanew(0x3C) → PE 签名 → 可选头
      → 偏移 +48 处 2 字节 = MajorSubsystemVersion


────────────────────────────────────────────────
  三、不是内存完整性（HVCI）—— 这条很重要
────────────────────────────────────────────────

  很容易误判成 HVCI，因为：
      · 机器是 Win11，HVCI 默认开着
      · 驱动是 2017 年的
      · 现象都是"加载失败"

  实测反证（同一台机器、HVCI 全程开着）：

      sc start ZLGCAN     (usbcan.sys 2017)     → 193  失败
      sc start USBCAN_E   (USBCAN_E_U.sys 2020) → RUNNING 成功

  ★ 2020 年的驱动在 HVCI 开着的情况下能正常加载，
    说明 HVCI 不是拦截原因。关掉内存完整性对这个老驱动【没有用】。

  ★ 代价提醒：内存完整性是实打实的内核保护，为它关掉不值得，
    而且关完也不会好。


────────────────────────────────────────────────
  四、重装驱动/重装 ZCANPRO 也没用（已实测）
────────────────────────────────────────────────

  跑了包里的 ZLG-USBCAN-AllInOne.exe /S（管理员，退出码 0）：

      usbcan.sys SHA256 前 16 位
          装之前: 13919677B0084B1D
          装之后: 13919677B0084B1D     ← 完全没变
          修改时间: 2017-12-20 19:18:04

      sc start ZLGCAN  →  仍然错误 193

  安装包装的就是同一个 2017 年文件，驱动本身没被替换/修复。

  ★ 如果有人说"重装一下就好了"，先确认那台机器的 Windows 版本 ——
    在较老的 Windows（Win10 早期、Win7）上这个驱动是能加载的，
    所以"重装能好"可能是版本差异带来的错觉。


────────────────────────────────────────────────
  五、这台机器上能用什么
────────────────────────────────────────────────

  ✅ USBCAN-E-U（2020 驱动 2.3.0.6，子系统版本 6.1）
       驱动服务 USBCAN_E 在 Win11 25H2 上正常运行
  ✅ Vector VN1630A（全家通过，141 帧 / 0 错误）
  ✅ PEAK PCAN-USB（发送验证过）
  ✅ 创芯 CANalyst-II（2500 帧验证过，在另一台机器）

  ❌ ZLG 老款 USBCAN-II（2017 驱动，子系统版本 1.10）
       在这台机器上无论怎么装都起不来


────────────────────────────────────────────────
  六、遇到同类问题的排查顺序
────────────────────────────────────────────────

  1. 先看设备管理器有没有黄色感叹号
       有 → 是驱动/设备问题，别去查桥
       没有 → 再查桥

  2. 拿 ProblemCode
       Get-PnpDeviceProperty -InstanceId <id> |
         Where-Object KeyName -match 'ProblemCode'
       39 / 0xC000007B → 映像不可用（版本或架构不匹配）
       28             → 驱动没装
       10             → 设备无法启动

  3. 手动 sc start <服务名> 拿真实错误码
       193/0xC000007B → 子系统版本或架构问题
       Access denied  → 需要管理员

  4. 读 PE 头的 MajorSubsystemVersion
       < 6.0 → 新系统加载不了，换驱动或换机器

  5. 对比同厂家更新驱动的子系统版本
       如果新版是 6.1、老版是 1.10 → 可以确定是驱动老，
       关 HVCI / 重装安装包都没用
