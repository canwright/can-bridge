────────────────────────────────────────────────
  二、真正的缺口（按严重性）
────────────────────────────────────────────────

  【已修】错误帧被当数据 —— 三家都会犯

      Vector  2026-11-05 修（实测发 19 帧能"收"到 9350 帧）
      PCAN    2026-11-06 修（MSGTYPE 0x40 / 0x80）
      Kvaser  2026-11-06 修（flag 0x20 / 0x40）

      统一规则：接收时看到"错误帧 / 状态帧 / TXACK"标志，
      一律丢弃 + 计数，绝不交给上层。它们在 VCI 里没有对应类型，
      交上去只会被当成正常报文。

      实测依据：CAN 没有 ACK 就不会完成传输，驱动把每次失败重试
      都报成一个"接收事件"，id/data 还是原来那帧。

  【未修】TOSUN 的错误帧标志

      TLIBCAN.FProperties 里哪个位表示错误帧，没有拿到确切文档。
      现在只映射了 0x04=扩展帧、0x02=远程帧。
      **没有硬件，暂不处理。**

  【未修】错误状态回传：PCAN / TOSUN / Kvaser

      VCI_ReadErrInfo 对这三家走 ZeroMemory —— 永远报"无错误"。
      总线关闭了上位机也不知道。
      **没有硬件，暂不处理。**

  【未修】验收滤波只有 Vector 实现

      Vector   按 AccCode / AccMask 过滤 ✓
      其余五家 全收全给 ✗

      影响：上层设了滤波却收不到效果，高负载时拖慢上位机，
      但**不会出错数据**（只是多给了）。
      **没有硬件，暂不处理。**

────────────────────────────────────────────────
  四、CAN FD —— 决定暂缓，路线记在这里
────────────────────────────────────────────────

  ★ 为什么冒充 USBCAN-II 就永远没有 FD

      USBCAN-I  （型号 3）= CAN 2.0 设备
      USBCAN-II （型号 4）= CAN 2.0 设备

      假装成一块不支持 FD 的卡，对外就不可能提供 FD ——
      无论底下那块盒子多能干。

  ★ FD 型号在 ZCANPRO 里挂的是别的 DLL（新 API 段）

      [KERNELDLL_ZLG_CAN]
          2=USBCANFD.dll      41 32 1
          3=USBCANFD.dll      42 32 1
          4=USBCANFD.dll      43 32 1
         18=USBCANFD800U.dll  59 32 1

      而老的 [KERNELDLL_VCI_CAN] 段（型号 1~47）里
      **根本没有 USB 的 FD 设备**。

  ★ 所以要 FD，必须换身份：冒充 USBCANFD.dll（型号 41/42/43）

      要做四块：
        1. ZCAN_TransmitFD / ZCAN_ReceiveFD 真实现（64 字节）
           —— 现在这两根是桩，直接返回失败
        2. FD 双波特率（仲裁段 + 数据段）
        3. devices_property 里配 FD 型号的 XML
        4. Vector 侧 xlCanFdSetConfiguration + FD 事件解析

  ★ 什么时候需要

      J1939 / CCP / 经典 UDS（8 字节）  → 不需要
      新车型的 UDS on CAN FD（64 字节） → 必须做

  决定：**暂缓**（2026-11-06）。当前所有现场需求都是经典 CAN。


────────────────────────────────────────────────
  五、怎么补一家新后端（照这个顺序）
────────────────────────────────────────────────

  1. 拿到厂家 DLL 和头文件，确认导出名（注意 stdcall 修饰 _name@N）
  2. 加一个 BE_xxx 枚举和 Probe 函数，插进自动探测链
  3. 实现 14 个导出里对应的分支
     · 最少要：Open / Close / InitCAN / Start / Transmit / Receive
     · 其余可以先返回失败，但不能崩
  4. **接收一定要过滤错误帧 / 状态帧 / TXACK**（这条最容易忘，
     Vector 和 PCAN 都在这上面踩过）
  5. 时间戳统一成 0.1 毫秒：纳秒/100000、微秒/100、毫秒*10
  6. 跑 tests\SelfCheck.exe 和 tests\VciListen.exe 验证
  7. 在本文第一节的表里把对应的 ✗ 改成 ✓，并注明是否真机验过
