────────────────────────────────────────────────
  一、这一轮改对了、但没保留的部分
────────────────────────────────────────────────

  改法本身是对的（Vector 的设计就是这样）：

    · 一个 port 管多通道：xlOpenPort 传组合 mask（如 0x3 = CAN1+CAN2）
    · 每路各自 xlCanSetChannelBitrate / xlActivateChannel（传各自的 mask）
    · 接收事件带 chanIndex，按它分流回各路
    · 因此接收必须改成"先把事件抽进桥内缓冲，再按通道取"
      —— 不能像原来那样"为某一路直接取"，否则别的通道的帧会被丢掉

  ★ 其中「接收泵 + 真实 GetReceiveNum」这一项**实测有效**：

        改之前：待收帧数 -> 1，Receive -> 1 帧
        改之后：待收帧数 -> 128，Receive -> 32 帧（一次取满）

    而且 VCI_GetReceiveNum 从硬编码返回 1 变成报真实帧数，
    上层不再空转。这一项**明天要单独捡回来**，它和多路无关，风险低。

    ★ 注意它必须自己做，不能靠"某个后端能预读数量"那个分支 ——
      Vector 的 xlReceive 是一次性抽干所有通道的。


────────────────────────────────────────────────
  二、卡住的地方：Vector 的 init 权限是"谁先占谁有"
────────────────────────────────────────────────

  规则：同一个通道，只有【第一个】打开它的应用拿到 init 访问权。
        后来的应用能拿到 port，但 permissionMask = 0。

  这导致下面这个链条，实测逐条踩中：

    【顺序 A】先开单路，再开组合
        单路 mask=0x1  → 成功，占住 CAN1
        组合 mask=0x3  → perm=0x0（CAN1 被自己占着，CAN2 也不给）
        → 多路打不开，只能保持单路

    【顺序 B】关掉单路，再开组合
        单路 0x1 → 关掉
        组合 0x3 → perm=0x2   ← 只给了 CAN2！CAN1 没释放
        → 数量没变（1 路），但**从 CAN1 换到了 CAN2**
          用户的线接在 CAN1，结果变成"打开成功、一帧没有"

    【顺序 C】发现 B 变差，想回退单路
        关掉组合 → 立刻开 0x1 → perm=0x0
        → **连单路都开不回来，整块设备打不开**

  ★ 关键教训：**Vector 的 init 权限释放有延迟，不能"关掉马上重开"。**
    需要给驱动时间（试过 Sleep(200)，不够；或者干脆别走这条路）。

  ★ 另一条教训：**"拿到权限的通道数没变"不等于"没变差"。**
    从 CAN1 换到 CAN2 数量一样，但功能没了。
    所以任何"重新打开"的动作都必须保证：拿到的通道是原来那个的超集，
    否则宁可不做。


────────────────────────────────────────────────
  三、明天可以试的方向（按风险从低到高）
────────────────────────────────────────────────

  【低风险】只做接收泵 + 真实 GetReceiveNum
      不碰 OpenDevice，风险最低，收益是上层不空转。
      已实测有效（128 待收 / 一次取 32 帧）。

  【中风险】组合 mask 作为第一个动作
      在任何一个 port 打开之前，先试组合 mask：
        · 此时没有任何通道被占用，理论上能一次拿到 0x3
        · 拿不到再走原来的单路三层重试
      这次没试成功是因为改动把代码搞乱了 —— 思路本身没验证过。
      ★ 实现要点：组合尝试必须在 `st = XL_ERR_NOT_IMPLEMENTED;`
        和单路 for 循环【之前】，且失败不能影响后面的单路重试。

  【高风险】多 port：每个通道一个独立 port
      xlOpenPort(mask=0x1) 开一个 port，xlOpenPort(mask=0x2) 再开一个。
      互不干扰，不需要"关掉重开"。缺点：要维护 port 数组，
      接收要分别从两个 port 取（这反而简单，不用 chanIndex 分流）。
      ★ 如果组合 mask 那条路一直不行，就走这条。
