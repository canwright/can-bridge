================================================================
  怎么让更多人搜到这个项目
================================================================

  项目本身不复杂，难点在于「别人根本不知道它存在」。
  下面按【投入产出比】从高到低排。


────────────────────────────────────────────────
  一、Topics（最高优先级，10 分钟见效）
────────────────────────────────────────────────

  位置：仓库首页右侧 About → 齿轮图标 → Topics

  逐个粘进去（每个回车确认），最多 20 个：

      can
      canbus
      can-bus
      zlg
      zcanpro
      peak-system
      pcan
      vector
      vxlapi
      canape
      dll-shim
      dll-proxy
      interoperability
      windows
      c
      automotive
      embedded
      usbcan
      chuangxin
      canaly

  说明：
    · GitHub 的搜索结果会按 Topics 匹配，这是最直接的曝光来源
    · 中英混着放：英文让人在全球搜到，拼音/品牌名让人在国内搜到
    · 别放与内容无关的热门词，会被判定为滥用


────────────────────────────────────────────────
  二、Description（搜索结果里的第一行）
────────────────────────────────────────────────

  位置：About → Description

  现用（英文，优先给国际搜索）：

      Multi-vendor CAN DLL shim — use a ZLG / PEAK / Chuangxin interface
      from software that only accepts one specific brand.

  如果想同时覆盖中文搜索，可以在 README 开头放中文关键词
  （Description 本身只有一行，塞不下两种语言）。


────────────────────────────────────────────────
  三、README 里的关键词（最被低估的一项）
────────────────────────────────────────────────

  GitHub 的站内搜索和 Google 都会索引 README 正文。
  但关键词必须**自然地出现在句子里**，堆砌会被降权。

  这个项目真正会被搜到的说法：

      「周立功 USBCAN-2E-U 用 CANape」
      「创芯 CANalyst 在 ZCANPRO 里用」
      「CANape 没有 Vector 硬件怎么办」
      「PCAN 盒子伪装成 Vector」
      「ZCANPRO 换别的牌子盒子」
      「USBCAN.dll 替换」
      「vxlapi.dll 自己实现」
      「CAN 盒 通用 驱动 转发」

  已经在 README 的「它解决什么问题」一节里覆盖了大部分。
  如果某个具体场景在 issue 里被反复问，就把它加进 README —— 
  那条 issue 的措辞往往就是别人搜索时用的词。


────────────────────────────────────────────────
  四、发到国内社区（曝光量最大的渠道）
────────────────────────────────────────────────

  优先级从高到低：

    1. 知乎
       「如何让 CANape 用非 Vector 的 CAN 盒子」这类问题下回答，
       附仓库链接。搜索"CANape 硬件"、"周立功 CANape"都能命中。

    2. 掘金 / 博客园
       技术长文：「我是怎么让 ZCANPRO 认出创芯盒子的」
       重点写踩坑（结构体 16/18 字节、36MHz 时钟、句柄泄漏），
       这些内容比代码本身更受欢迎。

    3. V2EX / 嵌入式论坛（阿莫、电子发烧友）
       简短贴 + 链接。

    4. B 站 / 视频
       「CAN 盒子互相冒充」这类演示视频传播很快。

  ★ 关键：先讲【问题】，再给链接。
    「我有一块创芯盒子，但 CANape 只认 Vector，所以我写了个桥」——
    这句话本身就是别人会搜的内容。


────────────────────────────────────────────────
  五、发到国际社区
────────────────────────────────────────────────

    · Reddit: r/CANbus, r/embedded, r/ReverseEngineering
    · Hacker News（Show HN: CAN DLL shim ...）
    · awesome 列表提 PR：
        awesome-canbus
        awesome-automotive
        awesome-embedded
      （找对应仓库提 PR，加一行链接和一句话说明）

  ★ 提 awesome 列表的 PR 时，先说清「为什么这个对别人有用」，
    否则维护者会当成广告拒掉。


────────────────────────────────────────────────
  六、Gitee 镜像（国内访问速度）
────────────────────────────────────────────────

  GitHub 在国内经常慢或打不开。建议同步一份到 Gitee：

    1. gitee.com 新建仓库 can-bridge
    2. 本地加第二个 remote：
           git remote add gitee https://gitee.com/<你的名字>/can-bridge.git
    3. 推送：
           git push gitee main

  以后每次改完推两次（或让 CI 自动同步）。

  ★ Gitee 的搜索权重在国内搜索引擎里比 GitHub 高。


────────────────────────────────────────────────
  七、Release（"download" 类搜索）
────────────────────────────────────────────────

  很多人搜的是「下载」而不是「开源」。

  建议打第一个 Release：

    git tag -a v0.1.0 -m "First public release"
    git push --tags

  然后在 GitHub 上编辑这个 Release：
    · 附上编译好的 exe / dll（打包成 zip）
    · 写清「哪些盒子验证过、哪些没验证」
    · 附 SHA256

  ★ Release 页会被搜索引擎单独索引，是"下载"类搜索的主要入口。


────────────────────────────────────────────────
  八、维护期的持续曝光
────────────────────────────────────────────────

    · 每个 issue 解答完，如果暴露了新场景，补进 README
    · 每加一个厂商后端，发一条 Release note
    · 在 README 顶部放一张能力矩阵表（已做），
      它会被人截图转发 —— 表格比段落更容易传播


────────────────────────────────────────────────
  一句话总结
────────────────────────────────────────────────

  这个项目的价值不在代码量，在【踩过的坑】。
  想让更多人找到它：把坑写成能被搜到的话，而不是把代码堆得更长。
