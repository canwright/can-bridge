# 建议加入 Agent 预设的条目（针对 CAN 硬件/驱动类长会话）

> 来源：2026-11-04 ~ 11-05 那次非常长的 CAN 桥调试会话。
> 以下每一条都对应一次真实的返工，不是凭空总结。

---

## 一、结构体与 ABI（最高优先级）

1. **任何 `typedef struct` 的尺寸/字段顺序，必须先从官方头文件或官方手册抄一遍，
   不许凭记忆。** 抄完在回复里引用出处（文件名 + 页码/行号）。
2. **加编译期尺寸断言**，尺寸不符直接编译失败：
   ```c
   typedef char ASSERT_X[(sizeof(X) == N) ? 1 : -1];
   ```
   实战价值：一次断言当场抓出 `VCI_BOARD_INFO` 被外层 `#pragma pack(1)`
   压成 79 字节（官方 80），这个偏差已存在很久没人发现。
3. **一对转换函数只许存在一份。** 抽到头文件，桥和单元测试引用同一份，
   否则测试测的是拷贝，等于没测。
4. **单位换算是重灾区**（毫秒 vs 纳秒、DLC 编码 vs 字节数）。
   换算只许在一个地方做，并在旁边注明单位。

## 二、打开 / 关闭 / 探测

5. **打开和关闭必须严格配对**：同一个型号、无条件执行、并且**打印返回值**。
   实战价值：用错型号关设备 → 驱动里留着"设备被占用" → 之后连厂家软件都打不开，
   只能重装厂家软件或重启电脑。
6. **探测阶段只能"看"，不能"动"。** 探测时调用 CloseDevice / ResetCAN 之类
   会改变设备状态的函数，会把已经插好的设备一起关掉，越探越坏。
7. **没有验证过的还原路径，绝不删除厂家文件。**
   尤其：不能因为"大小和我的 DLL 一样"就判断它是自己创建的。

## 三、验证纪律

8. **每改一次给一个哈希**（文件大小 + SHA1 前 12 位），
   并明确要求用户回报"装的是哪个哈希"。
   实战价值：一整天至少两次因为"测的是旧版"而得出错误结论。
9. **改完先给"验收判据"**：明确告诉用户日志里应该出现哪一行、返回什么值。
   没有判据的修复等于没修。
10. **能做无硬件单元测试的，就写测试。**
    例如结构体转换的往返测试（含 1 字节帧、远程帧、无时间戳、ID 位宽截断）。
    真机只能验证"通不通"，验证不了"有没有丢字段"。
11. **改一个后端之前，先把其它后端的回归路径在纸面上过一遍**，
    并在回复里列出来（哪个文件、哪条路径、为什么不受影响）。

## 四、排错方法

12. **遇到"打不开/收不到"，先要那个能分生死的数据，不要连续猜。**
    典型分水岭问题：
      · 卸载之后还崩不崩？        → 区分是桥还是宿主
      · 重装软件就好使，还是重启就好使？
         只重装就好使 = 文件层面
         必须重启     = 驱动/内核层面
    实战价值：用户一句"重装 ZCANPRO 就好使，不用重启"
    直接排除了内核驱动方向，把范围锁到文件，当天就定位了真因。

13. **区分"没信号"和"信号不对"**：
      0 帧 + 0 错误帧   → 没接 / 极性反 / 插错通道 / 句柄泄漏
      0 帧 + 万级错误帧 → 波特率或型号不对
    这两个数字比任何日志都先给出方向。

14. **日志里的数字要能自证。** 打印帧数时不要和"数据长度"混用同一个词；
    打印结构体时把原始字节一并打出来，按 16 进制对照。

## 五、会话管理

15. **多天/多轮的硬件调试，维护一个 `状态.md`**：
      - 当前版本哈希
      - 已验证 / 未验证的功能矩阵
      - 已知坑与对应症状
      - 下一步要的那一个数据
    每轮开头先读它。对话被压缩后，记忆会丢，文件不会。

16. **改动尽量小步、可回退**，每次只动一件事，并说明"如果这个改坏了，
    回退到哪个哈希"。

---

## 不建议改的部分

- **语言与风格**：中文、简洁、先给结论再给依据 —— 这套是有效的，别动。
- **诚实标注未验证**：不确定就说不确定，这条救过场（多次避免把猜测当结论）。
- **主动索要日志/截图**：比让 agent 自己脑补强得多。
