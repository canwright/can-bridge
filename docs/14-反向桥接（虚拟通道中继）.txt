================================================================
  反向桥接 —— 真实盒子 -> Vector 虚拟通道
  让 CANape 用上周立功 / PEAK 的盒子
================================================================

  这是和主桥【相反】的方向：

      主桥      真实硬件 -> 假装成周立功 -> ZCANPRO 能用
      反向桥接  真实硬件 -> 假装成 Vector -> CANape 能用


────────────────────────────────────────────────
  一、为什么需要它
────────────────────────────────────────────────

  真实场景（也是这个功能立项的原因）：

      出差时 VN1630 硬件出问题，但 CANape 的许可还在身上。
      借同事一块周立功，就能接着干活 —— 不用停工等人寄硬件。

  硬件会坏，许可不会。


────────────────────────────────────────────────
  二、为什么用"虚拟通道"，不写假 vxlapi.dll
────────────────────────────────────────────────

  两种做法：

    A. 假 vxlapi.dll —— 替掉 Vector 的 DLL，自己实现 340 个导出
       ✗ CANape 的许可检查也走 Vector 驱动。实测：装上探针 DLL 后
         CANape 加载了它，随即自己退出 —— 读不到许可就不让用。
       ✗ 要对着 CANape 的脾气实现几十上百个函数，猜错一个就崩。

    B. 虚拟通道中继（本目录这套）—— 用【真】Vector 驱动，一行不改
       ✓ 许可、驱动配置、所有 API 行为都是原厂的，CANape 完全无感。
       ✓ 我们要做的只有"搬帧"，一个 Vector API 都不用实现。

  实测确认（2026-11-06，无硬件）：
      进程 A 打开 Virtual Channel 1（app=SideA，perm=0x1）发帧
      进程 B 打开 Virtual Channel 2（app=SideB，perm=0x2）收帧
      → B 收到了 A 的帧。Vector 驱动把两路虚拟通道连成了一根虚拟电缆。


────────────────────────────────────────────────
  三、怎么用
────────────────────────────────────────────────

  准备：这个文件夹里要有
        RelayGui.exe
        VxlRelay.exe
        UniVciBridge.dll
        UniVciBridge.ini

  步骤：

    1. 插上周立功（或 PEAK）盒子，厂家驱动装好

    2. 双击 RelayGui.exe
       · 真实硬件   选"周立功"
       · 硬件通道   选盒子上的口（CAN1 / CAN2）
       · 虚拟通道   选第 1 路（我们占这一路）
       · 波特率     选和总线上一致的那个
       · 点【启动中继】

       会弹一个黑窗口，每秒刷新：
           虚拟->硬件 N 帧    硬件->虚拟 N 帧

    3. 打开 CANape
       · 设备选【另一路】虚拟通道（比如 Virtual Channel 2）
       · 波特率和上面一致
       · 就能收发了


────────────────────────────────────────────────
  四、一个改不了的事实（先说清楚）
────────────────────────────────────────────────

  CANape 里显示的是 "Virtual Channel N"，不是 "VN1630A"。

  这个名字是 Vector 驱动报的。要改成 VN1630A，就必须替换
  vxlapi.dll —— 而许可检查走那个驱动，替换后 CANape 不让用。

  所以：**功能完全正常，只是设备名不一样。**
  市面上同类产品（比如 SysMax 那套）也是这个样子。

  五、验证到哪一步了
────────────────────────────────────────────────

  ✅ 虚拟通道两进程互通        实测通过
  ✅ 中继拿到虚拟通道权限       perm=0x2

  ★ 也就是说：**骨架通了，但没在真机上跑通过一次完整链路。**
    第一次上机请按第三节走，把黑窗口里的两个计数都跑起来。


────────────────────────────────────────────────
  六、和主桥的关系
────────────────────────────────────────────────

  两套东西共用一个 UniVciBridge.dll：

      主桥      UniVciBridge.dll 改名成 USBCAN.dll 给 ZCANPRO 用
      反向桥接  同一个 DLL，被 VxlRelay.exe 当"硬件驱动"调用

  硬件后端由 UniVciBridge.ini 的 backend= 决定
  （RelayGui 会自动写这个文件）。


────────────────────────────────────────────────
  七、这个目录里有
────────────────────────────────────────────────

      VxlRelay.exe        中继引擎（面板会自己拉起它）
      UniVciBridge.dll    桥本体，中继用它访问真实硬件
      UniVciBridge.ini    配置（面板自动生成）
