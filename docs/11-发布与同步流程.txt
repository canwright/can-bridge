────────────────────────────────────────────────
  二、每次改完必须做的六步
────────────────────────────────────────────────

  □ 1. 编译

        cd src
        build-unibridge.bat
        → out\UniVciBridge.dll

  □ 2. 复制到主目录

        → 主目录\_prog\UniVciBridge.dll

        如果门面（zlgcan.dll / PCANBasic.dll）也改了，
        同步主目录\_prog\新老API门面\

  □ 3. 同步文档

        docs\*.txt  →  主目录\说明文档\

  □ 4. 更新主目录的「先看这个.txt」

        里面写了版本号和哈希，改完必须跟着改，
        否则现场看不懂自己装的是哪一版。

  □ 5. 核对：主目录的 DLL 哈希必须等于仓库 src\out 的

        历史上出过"包里还有一份旧 DLL"的事故
        （_prog\VN模拟\ 里留了个中间版本），
        所以要多查一次整个包，不能只看主那个。

  □ 6. 提交并推送

        git add -A
        git commit -m "..." 
        git push origin main


────────────────────────────────────────────────
  三、给现场发的时候发什么
────────────────────────────────────────────────

  情况 A：对方已经装过桥，只想升级
      发「桥更新包」：USBCAN.dll + 说明.txt
      他覆盖 ZCANPRO 目录的 USBCAN.dll 即可

  情况 B：对方全新安装
      发主目录（或去掉 drivers_setup 的精简包）
      让他双击「一键工具.exe」→【一键检测并修复】

  情况 C：对方机器上什么驱动都没有
      让他先装厂家驱动（Vector / ZLG / PEAK 官网下载），
      再装桥。顺序不能反。


────────────────────────────────────────────────
  四、几个不能碰的底线
────────────────────────────────────────────────

  · 不要动 USBCAN.dll.zlg.bak
    那是原厂 DLL 的备份，卸载和"真周立功优先"都靠它。
    一键工具已有保护：备份存在时不会覆盖。

  · 不要把两个版本的 UniVciBridge.dll 同时放进包里
    现场会拷错。包里只能有一份。

  · 不要在包里放厂家的驱动安装包去公开分发
    厂商 EULA 通常不允许二次分发。
    主目录里留着自用可以，对外发要剔掉
    （drivers_setup 占 141 MB，剔掉后整包只剩 1.3 MB）。

  · 提交前先跑自检

        tests\SelfCheck.exe          9 项全过
        tests\CtConvTest.exe         50 项全过
        tests\VxlLayoutTest.exe      8 项全过

    改过错误状态相关代码的，还要跑
        VciListen.exe 21 pollerr 500
    看日志涨不涨（正常几行，刷屏就是回归）。
    —— 这一条是 2026-11-06 加上的：那天发现"上位机高频轮询
       会刷爆日志"，而原来的测试只调一次，测不出来。


────────────────────────────────────────────────
  五、版本号怎么起
────────────────────────────────────────────────

  格式：v<日期>-<这一版的要点>

  例：
      v2026-11-05-zlgfirst   真周立功优先
      v2026-11-06-quietlog   日志不再刷屏

  要点用英文短词，不要用中文 —— 版本号会进日志和文件名，
  中文在部分环境下会乱码。
