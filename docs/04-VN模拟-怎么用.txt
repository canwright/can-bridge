────────────────────────────────────────────────
  这是干什么的
────────────────────────────────────────────────

  目标：把周立功 / PCAN 的 1~2 口盒子，模拟成 Vector VN1610 / VN1630，
        让 CANape 这类软件直接用。

  但 vxlapi.dll 有 575 个导出函数，手册里没有"CANape 到底用哪几个"。
  猜着写门面一定跑不通，所以第一步是【问】：
  放一个空壳进去，把所有调用记下来（函数名 + 参数 + 顺序），
  拿到清单后再实现那 20~30 个真正被调用的函数。


────────────────────────────────────────────────
  ★ 第 0 步（必须在有真 VN1630 的那台机器上先做）
────────────────────────────────────────────────

  同事那台机器有真 VN1630 —— 这是我们拿到"标准答案"的唯一机会。

  在动手改任何东西之前，先跑这个【只读】探针：

      双击  1-量真VN1630.exe
      （只读，不写文件、不改注册表、不动任何东西）

  把窗口输出全部发回来。里面会有：

      · VN1630A 的真实 hwType 编码   ← 手册里没写，只能这么拿
      · 通道名字符串（"VN1630A Channel 1" 之类）
      · 每路的总线参数（波特率等）
      · 相邻通道名的间隔 = 结构体真实步长（复核我们算的 227）

  有了这一份，我们报出来的设备才和真机一致，CANape 才会认。

  另外 2-校验布局.exe 也是只读的，跑一下更保险：
      它用我们算的结构体去读真 DLL 写的数据，
      8 项全过就说明布局没算错。



────────────────────────────────────────────────
  ★★ 装法：不改 CANape 任何一个现有文件 ★★
────────────────────────────────────────────────

  原理（已在本机 Win11 实测通过）：
    Windows 加载 DLL 时，如果程序目录下存在名为
        <程序名>.exe.local
    的【文件夹】，加载器会先搜这个文件夹，再搜程序目录。

    所以我们只在 CANape 目录里【新增一个文件夹】，
    CANape.exe 和原厂 vxlapi.dll 都保持原样。

  ── 步骤 ──

  1. 关掉 CANape

  2. 找到 CANape 安装目录（CANape.exe 所在的那个目录）

  3. 在里面【新建文件夹】，名字必须精确是：
         CANape.exe.local
     （就是 exe 的名字后面加 .local）

  4. 把本文件夹里的 VxlApiStub.dll 复制进这个新文件夹，
     并改名成：
         vxlapi.dll

  5. 装完长这样：
         CANape 安装目录\
         ├── CANape.exe          ← 没动
         ├── vxlapi.dll          ← 没动（原厂的）
         └── CANape.exe.local\   ← 新增的文件夹
                 vxlapi.dll     ← 我们的探针

  ── 如果 CANape 目录里本来【没有】vxlapi.dll ──
    说明它是从系统目录加载的，那第 3 步一样做就行，
    .local 里放我们的探针同样会优先命中。


────────────────────────────────────────────────
  用（很短的测试就够）
────────────────────────────────────────────────

  1. 打开 CANape
  2. 走到「选择设备 / 配置通道 / 连接 VN1630」那一步
     （能点多深点多少，不用真的连上总线）
  3. 关掉 CANape
  4. 找日志：
         CANape 安装目录\CANape.exe.local\vxlapi_stub.log
         或 %TEMP%\vxlapi_stub.log
  5. ★ 把 vxlapi_stub.log 发回来

  日志里如果【一行都没有】，说明 CANape 是按完整路径加载 vxlapi 的，
  .local 没起作用 —— 这个信息本身也很关键，也请告诉我。


────────────────────────────────────────────────
  卸（两种都行，都不影响原厂）
────────────────────────────────────────────────

  方式一（最干净）：
        直接删掉 CANape 目录里新建的那个
            CANape.exe.local
        整个文件夹。删完就和没装过一样。

  方式二：
        双击本文件夹里的「一键恢复.exe」
        它会自动找 CANape / ZCANPRO / CANoe 目录，
        还原 xxx.dll.canbridge.bak 之类的备份
        （.local 方式没有备份需要还原，删文件夹即可）


────────────────────────────────────────────────
  ★ 为什么这个装法是安全的
────────────────────────────────────────────────

  · CANape.exe              没动
  · 原厂 vxlapi.dll         没动
  · C:\Windows\System32     没动
  · CANoe / Vector 自家工具  不受影响（它们不读 CANape.exe.local）
  · 恢复 = 删一个文件夹

  万一 .local 机制在你的 Windows 版本上不生效，最坏结果也只是
  "探针没被加载、日志为空"，不会弄坏 CANape。


────────────────────────────────────────────────
  备选装法（如果 .local 不生效）
────────────────────────────────────────────────

  只在确认 .local 无效后才用这个，侵入性更高：

    1. 先给原厂的改名：vxlapi.dll → vxlapi.dll.canbridge.bak
    2. 把 VxlApiStub.dll 复制进去，改名 vxlapi.dll
    3. 测完用「一键恢复.exe」，它会按 .canbridge.bak 还原

  ★ 不管哪种装法，都不要动 C:\Windows\System32 里的 vxlapi.dll。


────────────────────────────────────────────────
  常见问题
────────────────────────────────────────────────

  Q: CANape 打不开 / 提示找不到设备？
  A: 正常。空壳不实现功能，只记日志。

  Q: CANape 直接崩了？
  A: 也正常（某个返回结构体的函数我们返回了 0）。
     日志里崩之前的最后几行最关键，一起发回来。

  Q: 日志是空的？
  A: 说明探针没被加载 —— 请把 CANape 安装目录截图发我，
     我看一眼就知道该怎么调整。

  Q: 会不会把 CANoe 也搞坏？
  A: 不会。只动 CANape 目录里新建的那个文件夹。
