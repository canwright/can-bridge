────────────────────────────────────────────────
  ☐ 1. 设 Topics（效果最大，10 分钟生效）
────────────────────────────────────────────────

  位置：仓库首页 → 右侧 About → 齿轮图标 → Topics

  逐个粘，每粘一个按回车：

      can
      canbus
      can-bus
      zlg
      zcanpro
      peak-system
      pcan
      vector
      vxlapi
      canape
      canoe
      dll-shim
      dll-proxy
      interoperability
      usbcan
      chuangxin
      automotive
      embedded
      c
      windows

  ★ 为什么最重要：
    实测过 —— 用 "zcanpro" 搜，结果里没有这个仓库，
    因为 GitHub 仓库搜索只匹配「仓库名 + 描述 + Topics」，不搜 README。
    Topics 是空的时候，README 里写满关键词也没用。


────────────────────────────────────────────────
  ☐ 2. 改 Description（搜索结果的第一行）
────────────────────────────────────────────────

  位置：About → Description

  粘这个：

      CAN DLL shim - use a ZLG USBCAN / PEAK PCAN / Chuangxin interface from
      ZCANPRO, CANape or CANoe, or any host that only accepts one brand.
      Fake vxlapi / USBCAN.dll for CAN bus interoperability.

  ★ 关键：把 ZCANPRO、CANape、CANoe、vxlapi、USBCAN.dll
    这些"别人真会去搜的词"放进描述，否则按这些词搜不到你。


────────────────────────────────────────────────
  ☐ 3. 启用 CI（30 秒，网页上建文件）
────────────────────────────────────────────────

  仓库页 → Add file → Create new file
  文件名：  .github/workflows/build.yml
  内容：    docs\ci-build.yml.txt 的全文
  提交。

  ★ 为什么不用 git push：
    改 .github/workflows/ 需要令牌带 workflow 权限，
    只有 repo 权限会被 GitHub 拒绝。网页建文件用你的登录会话，没这个问题。

  启用后每次提交会自动：32 位编译全部源码、跑 50 项 + 8 项测试、
  并拦截厂商 DLL / 厂商 PDF / 编译产物被误提交。


────────────────────────────────────────────────
  ☐ 4. 让同事点个星（哪怕 5 个）
────────────────────────────────────────────────

  GitHub 的搜索排名里，星数是权重。
  0 星的新仓库会排在几年前的、几十星的仓库后面。

  实测：搜 "can-bridge" 有 2950 个结果，
        一个有 21 星的同名仓库（linker-bot/can-bridge）排在你前面。


────────────────────────────────────────────────
  ☐ 5. 打第一个 Release（吃"下载"类搜索）
────────────────────────────────────────────────

  很多人的搜索词是「XXX 下载」，不是「XXX 开源」。

  本地（装好 git 后）：

      git tag -a v0.1.0 -m "First public release"
      git push --tags      (github.com 可能连不上，见下方备注)

  然后在网页上编辑这个 Release：
      · 上传编译好的 exe / dll，打包成 zip
      · 写清哪些盒子验证过、哪些没验证（照 README 的能力矩阵抄）
      · 附 SHA256

  ★ Release 页会被搜索引擎单独索引，是"下载"类搜索的主要入口。


────────────────────────────────────────────────
  ☐ 6. 发一篇（真正带来人的地方）
────────────────────────────────────────────────

  这个仓库里已经备好两篇草稿：

      docs\article-1-技术长文.txt     掘金 / 公众号 / 知乎专栏
      docs\article-2-问答版.txt       知乎回答 / V2EX / 论坛

  ★ 核心事实：
    GitHub 站内搜索带来的流量约等于 0。
    别人不是"搜到一个工具"，而是"遇到一个问题，搜到一个答案"。
    所以发帖子 > 改描述 > 设 Topics。


────────────────────────────────────────────────
  ☐ 7. 同步到 Gitee（国内访问）
────────────────────────────────────────────────

  1. gitee.com 新建空仓库 can-bridge
  2. 本地：

        git remote add gitee https://gitee.com/<你的名字>/can-bridge.git
        git push gitee main

  ★ Gitee 的搜索在国内引擎里权重比 GitHub 高，
    而且访问速度对国内用户友好得多。


────────────────────────────────────────────────
  ☐ 8. 等搜索引擎收录（几周到几个月，急不了）
────────────────────────────────────────────────

  Bing / Google 收录新仓库一般要几天到几周。
  百度对 GitHub 的收录更慢。

  能做的是：发帖子时链接到仓库，外部链接会加快收录。


────────────────────────────────────────────────
  备注：这台机器上推 GitHub 的办法
────────────────────────────────────────────────

  github.com:443 在本机是不通的（git push 会报 Could not connect），
  但 api.github.com 是通的。

  所以要用 REST API 提交，脚本在：
      CanBridge\_push_api.py

  流程：读令牌 → 传 blob → 造 tree → 造 commit → 移动 ref。
  等价于 git push，只是不走 git 协议。

  ★ 用完立刻删令牌。经典令牌改不了 .github/workflows/，
    那个只能在网页上建（见第 3 项）。

  · 摘要别用自动提取，会自动抓正文前 256 字，容易抓出过时的说法。
