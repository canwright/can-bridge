================================================================
  在同事电脑上能做的测试清单
  —— 只有 VN1630A + 现场那条总线，不需要额外硬件
================================================================

  前提：桥已经装好（v2026-11-06-errall 或更新），VN1630A 插着，
        CAN 线接在 CAN1，ZCANPRO 能收到报文。

  每一项都写清了：怎么做 → 看什么 → 什么算通过 → 不通过怎么办。


────────────────────────────────────────────────
  测试 1：单通道模式（channels=1）生效
────────────────────────────────────────────────

  为什么测这个：
      之前默认暴露 2 路，CAN2 没接线会一直累计总线错误。
      实测到过 35718 个错误计数，界面很吓人。

  怎么做：
      1. 打开 ZCANPRO 目录\UniVciBridge.ini
      2. 确认里面有这一行：      channels=1
      3. 关掉 ZCANPRO 再打开
      4. 打开设备 → 启动通道0 → 收一分钟报文

  看什么：
      · 设备管理里是不是只有【通道0】在跑
      · 右下角"错误帧计数"是多少

  通过标准：
      错误帧计数 = 0（或几十以内，偶发干扰正常）

  不通过：
      还是几万 → 说明 channels=1 没生效，把日志发我


────────────────────────────────────────────────
  测试 2：发送方向 —— 上位机发出去的帧到总线上了吗
────────────────────────────────────────────────

  为什么测这个：
      到目前为止所有"发送成功"只证明函数返回 0，
      没证明帧真的到了总线上。这是最大的未验证项。

  怎么判断"帧真的上总线了"（不需要第二个工具）：
      CAN 协议要求总线上有别的节点给 ACK。
      **如果发出去的帧没人应答，错误帧会立刻往上涨。**
      反过来：**发送帧数 +1、错误帧不涨 = 帧被 ACK 了 = 真的发出去了。**

  怎么做：
      1. 上表勾选"通道0"
      2. 点顶部【发送数据】
      3. 新建一条报文：
             ID    = 0x123（随便，别和总线上的 ID 冲突）
             类型  = 标准帧 / 数据帧
             长度  = 8
             数据  = 11 22 33 44 55 66 77 88
      4. 点【发送】一次（不要周期发送）
      5. 看右下角三个计数

  看什么：
      接收帧计数  → 应该继续涨（总线还在收）
      发送帧计数  → 应该 +1
      错误帧计数  → 应该【不动】

  通过标准：
      发送帧 +1，错误帧不涨

  不通过：
      发送帧不涨 → 发送没成功，看日志
      错误帧暴涨 → 帧发出去了但没人 ACK（总线问题或 ID 冲突）


────────────────────────────────────────────────
  测试 3：长跑 10 分钟（时间戳 + 稳定性）
────────────────────────────────────────────────

  为什么测这个：
      时间戳以前每 4.29 秒往回跳；稳定性只跑过 150 秒。

  怎么做：
      1. 启动通道0，正常收报文
      2. 让它跑满 10 分钟，中间不要动
      3. 右键报文列表 → 保存为 ASC（或点【保存】）

  看什么：
      · 界面有没有卡死、掉线、报文停止
      · 保存的 ASC 文件里时间戳那一列

  通过标准：
      · 10 分钟不掉线不卡
      · 时间戳从 0 一直涨到 600 秒左右，**中途没有往回跳**
      · 不应该出现 0.000000 这种值

  不通过：
      时间戳回绕 → 把 ASC 前 200 行发我
      卡死/掉线   → 把 UniVciBridge.log 发我


────────────────────────────────────────────────
  测试 4：拔插恢复
────────────────────────────────────────────────

  为什么测这个：
      现场最常见的是"拔了再插就再也打不开，只能重启电脑"。

  怎么做：
      1. 收着报文，直接把 VN1630A 的 USB 拔掉
      2. 等 3 秒
      3. 插回去
      4. 在 ZCANPRO 里【关闭设备】→【打开设备】→【启动通道0】

  通过标准：
      能重新收到报文，不需要重启电脑、不需要重开 ZCANPRO

  不通过：
      打不开或者打开了收不到 → 拔插两次再试；
      还不行 → 把日志发我（这次的日志会显示端口有没有释放）

────────────────────────────────────────────────
  测试 6：两路独立（有两条总线才做）
────────────────────────────────────────────────

  前提：CAN1 和 CAN2 各接一条【不同的】总线。
        如果只有一条线，跳过这项。

  为什么测这个：
      之前验的"两路"是两个口接同一条线（同一帧两路各收一份），
      没验过"两条独立总线各自只收自己的"。
      如果分流出错，会把 A 的帧串到 B 上。

  怎么做：
      1. ini 里改成  channels=2
      2. 打开设备，通道0 和通道1 都启动
      3. 开两个视图，一个看通道0、一个看通道1

  通过标准：
      两个视图里的报文 ID 完全不同（各自只看到自己那条线）

  不通过：
      两边报文一样 → 分流错了，把日志发我


────────────────────────────────────────────────
  测不了的两项（需要额外条件）
────────────────────────────────────────────────

  PEAK 盒子接收
      需要一块 PCAN-USB 和 VN 接同一条线。
      现场没有 PCAN 盒子就测不了。

  zlgcan.dll / PCANBasic.dll 门面
      需要用【真实的上位机软件】，不是我们的测试工具。
      如果哪台机器上装了用周立功新 API 或 PEAK API 的软件，
      把门面装过去试才有意义。


────────────────────────────────────────────────
  出问题要给我的三样东西
────────────────────────────────────────────────

  1. ZCANPRO 目录\UniVciBridge.log（整个文件，不要只截几行）
  2. 诊断工具\自检.exe 的结果截图
  3. 出问题时的界面截图（尤其右下角三个计数）

  有这三样，基本能定位到具体是哪一步。
