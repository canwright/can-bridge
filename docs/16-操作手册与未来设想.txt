一、现在手上有三样东西
================================================

  ① 主桥（周立功盒子 → ZCANPRO）
  ------------------------------------------------
      位置：_prog\
      作用：让 ZCANPRO 用上周立功 / PEAK / 广成 / Kvaser 任意一家盒子
      原理：替换 ZCANPRO 目录里的 USBCAN.dll，转发给真实驱动
      状态：真机验证 2242 帧 / 0 错误，稳定

  ② 虚拟通道中继（周立功盒子 → CANape / CANoe）
  ------------------------------------------------
      位置：虚拟通道中继（给CANape用）\
      作用：让 CANape 通过 Vector 虚拟通道使用周立功盒子
      原理：Vector 虚拟通道 + 中继软件 + 32 位辅助进程
      状态：双向验证 10/10，转发误差参考同行数据 <1ms

  ③ VN1630 门面（周立功盒子 → 只认 VN1630 的 32 位软件）
  ------------------------------------------------
      位置：_prog\VN模拟\ 与 反向桥接相关的产物
      作用：让只调 vxlapi 的 32 位软件看到一块"VN1630A"
      原理：替换 vxlapi.dll，报假设备信息，收发转给周立功
      状态：ReadTCUVersion 实测连接成功、收发 20/20
      限制：只能骗"只调 API"的软件，骗不了 CANape/CANoe
            （它们读的是 Vector 驱动枚举的设备接口）


二、各自的用法（都是一页纸）
================================================

  ① 主桥
      1. 双击 一键工具.exe → 安装
      2. 打开 ZCANPRO → 正常使用
      3. 卸载也是一键

  ② 虚拟通道中继
      1. 插周立功盒子（驱动装好，设备管理器无感叹号）
      2. 双击 启动中继.bat，按提示填型号 / 虚拟通道 / 波特率
      3. CANape 里选【另一条】虚拟通道（中继占一条，上位机用另一条）
      4. 中继窗口必须一直开着

  ③ VN1630 门面
      1. 把 vxlapi.dll 和 UniVciBridge.dll 放进目标软件目录
      2. 从 ZCANPRO 目录复制 USBCAN.dll 过来
      3. 打开软件，设备里会出现 VN1630A Channel 1~5


三、日常维护（很简单）
================================================

  需要改的地方
  ------------
    · 盒子型号：UniVciBridge.ini 里的 device_type
        4  = USBCAN-II（最常见）
        21 = USBCAN-2E-U
        20 = USBCAN-E-U
    · 波特率：ini 里的 baud，或启动时填
    · 虚拟通道：启动时填索引（本机 2 条，5 和 6）

  换电脑时要检查的三件事
  ----------------------
    □ Windows 的【内存完整性】是否关闭
        （开着的话，2017 年的周立功驱动加载不了，设备管理器会报错误 39）
    □ 周立功驱动是否正常（设备管理器无感叹号）
    □ Vector 驱动是否装好（要有 Virtual CAN Bus）

  出问题看哪里
  ------------
    · 中继黑窗口有没有打印"周立功盒子就绪"
    · Vector 通道 perm 是不是 0x0（0x0 = 被别的程序占了）
    · 中继和上位机是不是占了同一条虚拟通道（必须不同）


四、法律边界（写给未来的自己）
================================================

  可以做的
  --------
    · 用自己买的正版许可，配合自己的硬件
    · 在自己的机器上替换 DLL，用完还原
    · 内部使用、同事之间共享经验

  不要做的
  --------
    · 不要对外销售这套东西 —— 用别家商标（VN1630A）卖产品有风险
    · 不要把厂商的原版 DLL 打进交付包 —— 让用户从自己装的驱动里取
    · 不要绕过任何许可机制 —— 我们从来没做过，以后也别做

  一句话
  ------
    我们替代的是硬件，不是软件许可。
    软件该买就买，硬件该换就换。


五、未来可以怎么走（畅谈）
================================================

  方向一：把主桥做扎实（性价比最高）
  ------------------------------------------------
    现在主桥已经能用，但只覆盖"ZCANPRO 生态"。
    如果继续投入，最值钱的是【稳定性】而不是新功能：
      · 长时间跑（8 小时以上）不崩、不掉帧
      · 换 USB 口、拔插、休眠唤醒后能自动恢复
      · 日志能说清楚每一次断线的原因

    这三个做到，这东西就敢给同事用了。

  方向二：把虚拟通道中继做稳（覆盖 CANape/CANoe）
  ------------------------------------------------
    技术上已经通了，短板在体验：
      · 现在是命令行，做成一个能配置的小窗口
      · 开机自启、断线自动重连
      · 加一个"当前转发帧数 / 丢帧数"的实时显示

    这是唯一能覆盖 CANoe/CANape 的软件路线。
    但永远有个天花板：时间戳精度、没有原生错误帧、没有负载率。

  方向三：设备级模拟（SysMax 走的路）
  ------------------------------------------------
    要真正"像" Vector 设备，必须在驱动层做：
      · 虚拟 USB 设备（usbip-win + 协议模拟）
      · 或自研内核驱动（要 EV 签名证书）

    这需要逆向 Vector 的私有 USB 协议，是几个月的活,
    而且有蓝屏风险。一个人做不值得。

  我的建议
  --------
    1. 主桥优先 —— 它是唯一"真能替代硬件"的部分，而且已经能用
    2. 中继当辅助 —— 需要连 CANape 时用，接受它的限制
    3. 设备级模拟 —— 除非要做成产品卖，否则不碰

  最后一句
  --------
    这个项目最有价值的不是代码，是【这一套判断】：
      哪一层能改、哪一层改不了、为什么改不了。
    代码会过时，这个判断不会。
